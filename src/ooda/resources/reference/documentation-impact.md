# Documentation impact

Before handoff, ask whether the mission changed how the system or research should
be understood: domain concepts, architecture boundaries, data/authority flows,
interfaces, operator workflows, methodology or evidence gates, public commands, or
a durable negative finding worth preserving.

If nothing changed: `DOCUMENTATION: none — conceptual surface unchanged`.

If something did, update the smallest durable artifact inside allowed scope.
Prefer diffable Markdown. Substantial structural change may warrant an
`architect`; consequential truth-checking may warrant a `validator`. Do not create
a documentation role by default, and do not document for its own sake.
