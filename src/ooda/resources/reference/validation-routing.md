# Validation routing

Independent validation exists for independent error detection, not ceremony.
Route by consequence.

| Class | Examples | Default |
|---|---|---|
| **low** | deterministic reversible fix, formatting, small local bug | self-check and tests; no validator |
| **medium** | exploratory quantitative research, meaningful architecture, data transformation | deterministic checks always; independent validator only if uncertainty or risk warrants |
| **high** | qualification claim, production promotion, capital, security boundary, live data mutation, runtime safety, sealed-evidence interpretation | independent validation required |

Any single high signal makes the whole task high.

Deterministic checks are preferred over prose at every level: PIT/as-of law,
split membership, holdout sealing, target construction, missingness and censoring
semantics, forbidden leakage fields, arithmetic identities, published-count
identities, constant-predictor and metric invariants, reproducibility hashes.

`ooda route-validation --signal ...` returns the class and route.

Never self-certify a consequential claim. Tests are evidence, not authority.
