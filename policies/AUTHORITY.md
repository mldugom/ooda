# Authority Policy

OODA separates capability from authority.

Unless a project explicitly grants narrower exceptions, agents may not:
- merge or force-push protected branches;
- self-certify their own consequential implementation or model;
- promote discovery/evidence to production/qualification by assertion;
- modify live financial execution;
- spend real capital;
- delete or rewrite protected research/data artifacts as cleanup;
- expand a bounded task into a materially different mission without a new decision.

Tests are evidence, not authority.

A PR is a proposed change, not merge authorization.

A model artifact is an output, not promotion authorization.

The default Integration Owners are the human owner and the review process the project defines. OODA provides decision provenance but does not automate away human gates merely for convenience.
